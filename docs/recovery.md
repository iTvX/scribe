# 故障恢复

先完成正在编辑的文字，并切到系统自带输入法。以下步骤针对 `/Library/Input Methods/Scribe.app` 中的正式版。

## 安装或更新后找不到中书

1. 等安装器显示完成，再重新打开输入法菜单。0.1.4 起安装器会在安装后刷新已启用的输入源列表。
2. 首次安装仍需在「系统设置 → 键盘 → 输入法」中添加「中书」。
3. 已添加但菜单缺失时，在自己的终端运行下面的命令，不需要 `sudo`：

   ```bash
   "/Library/Input Methods/Scribe.app/Contents/MacOS/Scribe" --refresh-input-menu
   ```

   命令会临时启用再停用一个未使用的系统键盘布局；不会主动切换当前输入源。执行后检查实际菜单并试打中文。
4. 若仍失败，记录安装版本、系统版本和命令输出，按 Bug 模板报告。不要删除整个系统输入源偏好或强制重启系统服务。

## 改配置后无法输入或部署失败

在输入法菜单打开用户目录，备份当前文件，再撤销最近的配置修改并重新部署。若启动保护提示本次没有加载 Rime，修正配置后「重新部署」仍可恢复通知和状态处理。第三方 Lua 问题可以先用不含该脚本的最小方案复现。

需要恢复导入前数据时，先退出中书，再在访达中保留当前 `~/Library/Scribe` 的副本，把旁边的 `Scribe backup ...` 恢复为 `Scribe`。重新选择中书并部署。不要把仍被输入法使用的词库目录直接覆盖。

退出命令：

```bash
"/Library/Input Methods/Scribe.app/Contents/MacOS/Scribe" --quit
```

## 设置提示冲突或外部链接只读

- 文件被其他编辑器修改：先保留外部编辑，再点「还原」重新读取，重新应用需要的修改。不要反复覆盖。
- 配置链接到中书目录外：备份后将链接替换为独立文件，再重新读取。新导入的可读链接已自动独立复制。
- 写后校验失败：以错误中显示的备份路径为准；先比较当前内容和备份。程序不会为了回滚而覆盖可能刚被其他程序写入的新内容。
